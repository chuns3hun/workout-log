## 2. 상태·데이터와 지켜야 할 규칙

| 데이터 | 어디에 있나 | 규칙 |
| --- | --- | --- |
| 종목 목록 | 첫 화면 상태 `_exercises` (처음 값은 코드의 예시 종목) | 이름이 비어 있으면 안 됨. 앞뒤 공백을 지운 이름이 이미 있으면 안 됨. 부위는 가슴/등/하체/어깨/팔 중 하나 |
| 주간 목표 | 첫 화면 상태 `_goals` (처음 값: 가슴 12, 등 12, 하체 9, 어깨 9, 팔 6) | 부위마다 1 이상 50 이하 정수 |
| 세트 기록 | 첫 화면 상태 `_records` | 무게 0~500, 횟수 1~100 정수. 규칙에 안 맞으면 저장하지 않음 |
| 선택한 종목 | 첫 화면 상태 `_selected` | 종목을 고르지 않으면 기록할 수 없음 |

계산해서 보여 주는 값(따로 저장하지 않음):

- 이번 주는 월요일 0시부터 센다.
- 부위별 남은 세트 = 목표 − 이번 주 그 부위 기록 수. 0보다 작아지면 0이고 "목표 달성"으로 보인다.
- 이번 주 남은 세트 = 부위별 남은 세트의 합. 목표를 넘긴 부위가 다른 부위의 남은 세트를 깎지 않는다.
- 직전 기록 = 그 종목의 기록 중 가장 마지막 것.

모든 데이터는 메모리에만 있어서 **앱을 끄면 처음 상태로 돌아간다.** 기기 저장(F6)은 12주차 작업이다.

## 3. 확인 기록

확인 방법은 세 가지로 나눴다.

- 분석: `flutter analyze`
- 검사: `flutter test` 위젯 테스트
- 직접 실행: Android 에뮬레이터(Android 17, API 37)에서 손으로 입력

환경은 Flutter 3.47.4, Dart 3.13.3, Windows 11이고, 확인일은 2026-11-16이다.

| 확인 | 입력 | 기대 결과 | 실제 결과 (직접 실행) | 검사 |
| --- | --- | --- | --- | --- |
| AC7 | 기록이 있는 종목 선택 | 직전 기록이 보임 | 미실행 | 통과 |
| AC8 | 기록이 없는 종목 선택 | "직전 기록 없음" | 미실행 | 통과 |
| AC9 | 기록 저장 후 같은 종목 다시 선택 | 방금 기록이 직전 기록으로 바뀜 | 미실행 | 통과 |
| F5-1 | 가슴 목표 10으로 저장 | "8 / 10세트", "2세트 남음" | 기대와 같음 | 통과 |
| F5-2 | 가슴 목표에 0, 51, 빈칸, abc | 저장 안 됨, "1 이상 50 이하 숫자를 입력하세요" | 기대와 같음 | 통과 |
| F5-3 | 가슴 15로 바꾸고 저장 없이 뒤로 가기 | 목표가 그대로(F5-1 다음이라 10) | 기대와 같음 | 통과 |

| F3-1 | "인클라인 벤치프레스", 가슴으로 추가 후 기록 | 칩에 나타나고 선택됨, 가슴 남은 세트 1 감소 | 미실행 | 통과 |

- `flutter analyze`: No issues found!
- `flutter test`: 14개 모두 통과 (10주차 AC1·AC2·AC4·AC6 포함)

테스트로 확인한 범위에도 한계가 있다. F5-2 테스트는 안내 문구가 나오고 화면이 닫히지 않는 것까지만 보고, 첫 화면에 돌아가 목표가 그대로인지는 보지 않는다. 처음에 AI는 이것까지 확인한다고 보고했지만 코드를 열어 보니 아니었다.

## 4. 실패·미실행·미완료와 다음 작업

실패했던 것

- F5를 push하다 거절됐다. 원격에 같은 파일(`lib/main.dart`, `test/widget_test.dart`)을 고친 F4 커밋이 먼저 올라가 있었다. `git fetch`로 바뀐 파일을 확인하고 `git pull --rebase`로 합쳤다. 충돌은 없었지만 자동으로 합친 코드를 믿을 수 없어서 analyze와 test를 다시 돌려 통과한 걸 보고 올렸다. 이후로는 작업 전에 `git pull`부터 한다.
- 11주차 기록 파일을 고쳐 놨는데, 편집기에 열려 있던 예전 내용이 다시 저장돼서 고친 부분이 사라진 적이 있다. 폴더 정리 커밋에서 다시 넣었다.

미실행

- 위 표에서 "미실행"인 항목(F4, 합계, F3 직접 실행)
- F3·F4·F5를 한 화면에서 이어서 써 보는 확인 (테스트는 기능별로 따로 통과)

미완료

- 중복 종목 검사는 글자가 완전히 같을 때만 막는다. "벤치프레스"와 "벤치 프레스"는 다른 종목으로 들어간다. 써 보면서 불편하면 다시 정한다.
- 목표 설정과 종목 추가를 빼면 현황과 세트 기록이 아직 첫 화면 하나에 모여 있다.

다음 작업 (12주차)

- F6 기기 저장: 앱을 껐다 켜도 종목, 목표, 세트 기록이 남게 한다. 패키지가 필요할 수 있어서 수업에서 써도 되는지 먼저 확인한다.
- 위 미실행 항목 직접 확인
- 중간발표

## 5. AI와 작업한 방식

F5와 F3는 안티그래비티(Review-driven 모드)에서 workout-log 폴더만 열고 작업했다. 둘 다 같은 순서로 했다.

1. PRD의 해당 기능만, 메모리 저장만, 패키지 없이 구현하고 먼저 계획만 보여 달라고 요청
2. 계획을 읽고 빠진 부분을 덧붙여 승인
3. 완료 보고를 실제 코드와 비교한 뒤 직접 실행하고 커밋

| 기능 | 요청 횟수 | 계획을 보고 덧붙인 것 |
| --- | --- | --- |
| F5 | 2회 | 저장하지 않고 뒤로 가기로 나왔을 때 기존 목표 유지 |
| F3 | 2회 | 기존 종목 이름 목록을 추가 화면에 넘길 것, 이름 앞뒤 공백 처리 |

F3 요청에는 PRD에 없던 "이미 있는 이름 금지"를 넣었다. 같은 이름이 두 개면 칩에서 구분이 안 되기 때문이다. 계획에 있던 "추가한 종목 자동 선택"은 요청하지 않았지만 추가하고 바로 기록하는 흐름에 맞아서 그대로 두었다. 둘 다 PRD에 반영했다.

남은 세트 합계는 안티그래비티가 아니라 Claude에게 코드 수정을 맡겼고, 실행과 테스트는 내 PC에서 했다.
