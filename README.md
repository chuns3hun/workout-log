# Workout Log

그날 상황에 맞춰 바꿔도, 목표는 지켜지는 운동 계획

앱프로그래밍기초 개인 앱 프로젝트 (Flutter)

## 어떤 앱인가

운동 순서를 정해 두는 대신 부위별 주간 목표(예: 가슴 12세트)만 정해 둔다.
운동하는 날에는 비어 있는 기구나 그날 하고 싶은 종목을 골라서 하면 되고,
앱은 이번 주에 부위별로 몇 세트가 남았는지 보여 준다.

## 핵심 기능

- 부위별 주간 목표 설정
- 이번 주 남은 세트 수 표시
- 종목 선택 후 무게·횟수 기록
- 종목별 직전 기록 표시

## 주차별 기록

### 9주차

**한 일**
- 교수님 피드백(운동 주제는 괜찮지만 너무 흔함)을 받고 문제와 핵심가치를 다시 정리함
- Hevy, 플랜핏 기능을 조사함. 운동 중에 종목을 바꾸는 기능은 이미 있어서, 계획 단위를 순서에서 부위별 주간 목표로 바꾸는 쪽으로 정함
- topic.md, analysis.md 작성, 지인에게 루틴이 틀어진 날 어떻게 하는지 물어봄
- `flutter doctor` 확인 (문제 없음)

**배운 것**
- 앱 주제의 차별점은 기능 목록이 아니라 어떤 문제를 다르게 보느냐에서 나온다
- 남은 세트처럼 계산할 수 있는 값은 저장하지 않고 기록에서 계산한다 (5주차 내용 다시 적용)
- PowerShell을 그냥 열면 `C:\WINDOWS\System32`에서 시작해서 clone이 권한 오류로 실패함 → 문서 폴더로 이동해서 작업
- API 키를 코드에 직접 넣으면 지워도 커밋 기록에 남는다. 키는 따로 빼고 `.gitignore`에 넣어야 함

**다음 주 할 일**
- 이번 주 화면 + 세트 기록 (AC1, AC2, AC4)

### 10주차

**한 일**
- 교수님께 주제 확정받음
- 수업 샘플 PRD 형식에 맞춰 PRD 작성. 근거를 사실·가정·미정·확인할 질문으로 나눔
- Flutter 프로젝트 생성 (`--project-name workout_log`, web·android)
- 첫 화면 구현: 부위별 남은 세트 표시, 종목 고르고 무게·횟수 기록, 입력 검증
- AC1, AC2, AC4, AC6 위젯 테스트 작성

**확인 결과**
- `flutter analyze` 문제 없음, `flutter test` 4개 통과
- Chrome에서 직접 실행해 AC1, AC2, AC4, AC6 확인

**배운 것**
- 폴더 이름에 `-`가 있으면 Dart 패키지 이름으로 못 써서 `--project-name`을 따로 줘야 한다
- `flutter create .`는 이미 있는 파일(README 등)은 건드리지 않는다
- `DateTime.weekday`는 월요일이 1이라서 `weekday - 1`일을 빼면 이번 주 월요일이 된다
- 위젯 테스트에서 화면 아래쪽 위젯은 `ensureVisible`로 먼저 보이게 해야 탭할 수 있다
- 9주차 스케치는 화면 3개였는데, 핵심 행동을 먼저 확인하려고 한 화면으로 합쳤다 (PRD 변경 기록에 남김)
