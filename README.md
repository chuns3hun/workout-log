# Workout Log

그날 상황에 맞춰 바꿔도, 목표는 지켜지는 운동 계획

앱프로그래밍기초 개인 앱 프로젝트 (Flutter)

## 어떤 앱인가

운동 순서를 정해 두는 대신 부위별 주간 목표(예: 가슴 12세트)만 정해 둔다.
운동하는 날에는 비어 있는 기구나 그날 하고 싶은 종목을 골라서 하면 되고,
앱은 이번 주에 부위별로 몇 세트가 남았는지 보여 준다.

## 핵심 기능

- 부위별 주간 목표 설정
- 이번 주 남은 세트 수 표시 (부위별, 전체 합계)
- 종목 선택 후 무게·횟수 기록
- 종목별 직전 기록 표시
- 종목 추가
- 기기 저장 (앱을 껐다 켜도 기록 유지)

**배운 것**

- `DateTime.weekday`는 월요일이 1이라서 `weekday - 1`일을 빼면 이번 주 월요일이 된다
- 위젯 테스트에서 화면 아래쪽 위젯은 `ensureVisible`로 먼저 보이게 해야 탭할 수 있다
- 9주차 스케치는 화면 3개였는데, 핵심 행동을 먼저 확인하려고 한 화면으로 합쳤다 (PRD 변경 기록에 남김)

**확인 결과**
- `flutter analyze` 문제 없음, `flutter test` 15개 통과
- F5는 에뮬레이터, F3·F4·합계는 Chrome에서 직접 확인 ([week11/check.md](week11/check.md))

**배운 것**
- AI 완료 보고를 그대로 믿으면 안 된다. 테스트가 확인한다고 한 범위가 실제 코드와 달랐다
- 다른 곳에서 같은 파일을 고친 커밋이 먼저 올라가 있으면 push가 거절된다. `git fetch`로 뭐가 바뀌었는지 보고 `git pull --rebase`로 합친 뒤, 테스트를 다시 돌려 보고 올렸다. 이제 작업 전에 `git pull`부터 한다
- 에뮬레이터를 껐다 켜면 `offline`으로 잡힐 때가 있다. adb를 재시작하거나 `--cold`로 다시 켜면 된다
- 화면은 오늘 날짜로 돌아가서 주 경계는 화면으로 확인할 수 없다. 계산 함수만 따로 테스트했다

- prd-check 스킬로 F6을 PRD 완료 기준과 대조하고 구현 현황 갱신

**확인 결과**
- `flutter analyze` 문제 없음, `flutter test` 20개 통과
- Chrome에서 기록·종목·목표를 바꾸고 새로고침, 껐다 켜기까지 확인. 안드로이드는 아직 확인 못 함 ([week12/check.md](week12/check.md))

**배운 것**
- 처음 실행할 때 넣던 예시 기록을 그대로 두고 저장을 붙이면 가짜 기록이 실제 기록에 섞인다. 예시 기록은 테스트 준비에만 쓰게 바꿨다
- 웹 저장소(localStorage)는 포트마다 따로다. `flutter run -d chrome`을 그냥 하면 매번 포트가 바뀌어서 저장이 안 된 것처럼 보인다
- 테스트에서는 `SharedPreferences.setMockInitialValues`로 저장소를 가짜로 바꿔서 확인할 수 있다. 대신 이건 실제 기기 저장을 확인한 게 아니다
- 정책에 "미실행을 통과로 쓰지 않는다"고 적어 놔도 AI가 테스트만 보고 "확인 완료"로 적었다. 정책은 기준이고, 결과는 직접 열어서 봐야 한다
