# 9주차 — 개인 앱 주제 정리

## 1. 주제 확인 상태

**조건부 확정**

- 9주차 수업에서 운동 기록 앱 주제를 확인받음
- 피드백: 운동 주제는 유지해도 되지만 너무 흔한 주제다. 문제와 핵심가치를 기능이 아니라, 내가 원하는 가치와 사람들이 필요로 하는 것으로 정리해 올 것
- 보완한 내용: 문제와 핵심가치를 다시 정하고, 기존 앱과 겹치지 않는 지점(계획의 단위)을 찾음 → 상세 내용은 `analysis.md`
- 재확인: 10주차 수업에서 확정받기 (교수님이 다음 주까지 확정해 오라고 하심)

## 2. 한 줄 요약

**그날 상황에 맞춰 바꿔도, 목표는 지켜지는 운동 계획**

운동 순서를 고정하지 않고 부위별 주간 목표만 정해 두면, 그날 원하는 운동을 해도 이번 주에 남은 목표를 확인할 수 있는 앱

## 3. 사용자와 문제

**사용자**
- 주 3회 이상 웨이트 트레이닝을 하고, 루틴을 스스로 짜서 운동하는 사람 (첫 사용자는 나)

**문제**
- 헬스장은 사람이 많은 시간에 기구가 차 있어서 루틴 순서대로 운동하기 어렵다
- 그날 컨디션이나 하고 싶은 운동도 매일 바뀐다
- 그러다 보면 계획에 없는 운동을 하게 되고, 이번 주에 어떤 부위를 얼마나 했는지 알 수 없게 된다
- 결국 계획이 한 번 꼬이면 그 주 계획 전체가 의미 없어진다

## 4. 선택 이유 (7주차와 달라진 점)

| | 7주차 | 9주차 |
|---|---|---|
| 주제 | 운동 기록 앱 | 주간 목표 기반 운동 계획 앱 |
| 문제 | 지난 기록이 기억나지 않음 | 계획이 매일 현실 때문에 틀어짐 |
| 가치 | 직전 기록 확인 | 계획을 바꿔도 목표는 지켜짐 |

- 7주차 문제는 기존 기록 앱들이 이미 해결하고 있어서 흔하다는 피드백을 받음
- 유사 앱을 조사해 보니 운동 중에 종목을 바꾸는 기능도 이미 있었다 (Hevy, 플랜핏)
- 하지만 두 앱 모두 계획이 "순서가 있는 루틴"이라서, 순서 자체가 매일 틀어지는 문제는 남는다
- 그래서 계획의 단위를 순서에서 **부위별 주간 목표**로 바꾸는 것을 이 앱의 차별점으로 정함
- 직전 기록 확인은 버리지 않고 성장을 확인하는 보조 기능으로 남김

## 5. 핵심 흐름

1. 부위별 주간 목표를 정한다 (예: 가슴 12세트, 등 12세트, 하체 9세트)
2. 운동하는 날 앱을 열면 부위별로 **이번 주에 남은 세트 수**가 보인다
3. 정해진 순서 없이, 비어 있는 기구나 하고 싶은 종목을 고른다
4. 무게와 횟수를 기록한다 (직전 기록이 같이 보인다)
5. 저장하면 해당 부위의 남은 세트가 줄어든다

## 6. 기능 범위

| 구분 | 기능 | 이유 |
|---|---|---|
| 필수 | 부위별 주간 목표 설정 | 계획의 기준 |
| 필수 | 남은 목표 표시 | 핵심가치를 확인하는 화면 |
| 필수 | 종목 선택 후 세트 기록 (무게·횟수) | 핵심 행동 |
| 필수 | 종목 추가 (종목명 + 부위) | 내가 하는 종목을 제한 없이 쓰기 위해 |
| 필수 | 종목별 직전 기록 표시 | 성장 확인 |
| 제외 | 기록 그래프, 통계, 캘린더 | 핵심 흐름 완성 후 응용 과목에서 |
| 제외 | 체중·사진 등 몸 변화 기록 | 이번 가치와 직접 관련 없음 |
| 제외 | 운동 추천, AI 기능 | 계획은 내가 직접 정하는 것이 이 앱의 방향 |
| 제외 | 로그인, 클라우드 동기화, 배포 | 서버가 필요하고 이번 범위를 넘음 |

## 7. 데이터

| 데이터 | 항목 | 규칙 |
|---|---|---|
| 종목 | 종목명, 부위 | 종목명은 비어 있으면 안 됨. 부위는 가슴/등/하체/어깨/팔 중 하나 |
| 주간 목표 | 부위, 목표 세트 수 | 1 이상 50 이하 정수 |
| 세트 기록 | 날짜, 종목명, 부위, 무게(kg), 횟수 | 무게 0 이상 500 이하 (맨몸 운동은 0), 횟수 1 이상 100 이하 정수 |

- 이번 주 완료 세트 수와 남은 세트 수는 따로 저장하지 않고 세트 기록에서 계산한다 (5주차에 정리한 원칙: 계산할 수 있는 값은 저장하지 않음)
- 한 주는 월요일부터 일요일까지로 계산한다
- 종목 하나에는 부위를 하나만 정한다 (예: 데드리프트 → 등)

## 8. 저장과 외부 의존

- 저장: 기기 내부 저장. 처음에는 메모리 리스트로 시작하고, 12주차에 기기 저장을 붙인다
  - 후보는 shared_preferences (개인 실험 앱에서 써 본 적 있음). 수업에서 다루는 방법을 확인한 뒤 확정
- 외부 의존: 없음 (서버, API, 로그인 없음)
- 개인정보: 수집하지 않음. 운동 기록만 기기에 저장

## 9. 위험

| 위험 | 대응 |
|---|---|
| 세트 수만 세면 무게나 강도가 반영되지 않음 | 성장은 직전 기록으로 따로 확인. 볼륨 계산은 이번 범위에서 제외 |
| 여러 부위를 쓰는 종목은 분류가 애매함 | 종목마다 주 부위 하나만 정함 |
| 저장 방식이 아직 정해지지 않음 | 12주차 전까지 확정. 그 전에는 앱을 끄면 기록이 사라진다는 한계를 둠 |
| 조사하지 못한 앱 중에 같은 방식이 있을 수 있음 | 조사 범위를 analysis.md에 적어 둠 |
| 5주 안에 다 못 만들 수 있음 | 필수 기능 중 목표 표시와 세트 기록을 먼저 완성 |

## 10. 앱 AC

| # | 유형 | 행동 | 기대 결과 | 확인 방법 | 상태 |
|---|---|---|---|---|---|
| AC1 | 정상(가치) | 가슴 목표가 12세트이고 이번 주에 가슴 8세트를 기록한 상태에서 화면을 연다 | 가슴 "4세트 남음"이 표시된다 | 샘플 기록 8개를 넣고 화면 확인 | 미실행 |
| AC2 | 정상(유연성) | 순서와 상관없이 덤벨 프레스(가슴)를 골라 세트 하나를 저장한다 | 가슴 남은 세트가 1 줄어든다 | 저장 전후 숫자 비교 | 미실행 |
| AC3 | 경계 | 지난주 일요일 가슴 기록이 있는 상태에서 이번 주 월요일에 화면을 연다 | 지난주 기록은 이번 주 완료 세트에 포함되지 않는다 | 날짜가 다른 샘플 기록으로 확인 | 미실행 |
| AC4 | 잘못된 입력 | 횟수를 비우거나 0, abc, 101을 넣고 저장한다 | 저장되지 않고 "횟수를 올바르게 입력하세요"가 표시된다 | 각 값을 하나씩 입력 | 미실행 |
| AC5 | 빈 상태 | 주간 목표가 하나도 없을 때 앱을 연다 | "주간 목표를 먼저 정해 주세요"가 표시된다 | 목표 없이 실행 | 미실행 |
| AC6 | 경계 | 목표보다 더 많이 기록한다 (가슴 13세트) | "목표 달성"이 표시되고 음수가 나오지 않는다 | 샘플 기록 13개로 확인 | 미실행 |

앱 코드가 아직 없어서 전부 미실행이다.

```

│   [ + 세트 기록 ]    │            │ 오늘 기록            │

          │                        └─────────────────────┘
          ▼                                  ▲

┌─────────────────────┐                      │
│ 가슴                 │                      │
│  벤치프레스           │──────────────────────┘
│  덤벨 프레스          │
│ 등                   │
```

## 12. 10주차 첫 작업과 준비 상태

**첫 작업**
- 화면: ① 이번 주 화면
- 핵심 행동: 세트 하나를 기록하면 해당 부위의 남은 세트가 줄어드는 것
- 관련 AC: AC1, AC2, AC4
- 범위: 목표는 코드에 고정, 저장은 메모리 리스트, setState만 사용

**준비 상태**

| 항목 | 상태 |
|---|---|
| 저장소 | `workout-log` (개인 저장소). README만 있음 |
| 현재 코드 | 구현 전 |
| 개발환경 | 수업 전에 `flutter doctor`로 확인 예정 |
| 실행 방법 | 프로젝트 생성 후 `flutter run -d chrome` |
| README | 7주차 기록 앱 내용이라 이번 주제에 맞게 수정 필요 |

**확인이 필요한 기술**
- 한 주(월~일)의 시작 날짜를 DateTime으로 계산하는 방법
- 기기 저장 방법을 수업에서 다루는지 (shared_preferences 등)
- 화면 사이에서 기록 리스트를 공유하는 방법 (지금까지는 화면 하나 안에서만 setState를 써 봄)
