# 11주차 확인 기록 — 주간 목표 설정(F5)

## 1. 이번에 한 것

- 안티그래비티(IDE)에 Dart·Flutter 확장을 설치하고, workout-log 폴더만 열어서 작업했다. 명령은 하나씩 승인하는 Review-driven 모드로 실행했다.
- PRD의 F5(주간 목표 설정)를 구현했다. 첫 화면 오른쪽 위 설정 아이콘을 누르면 "주간 목표 설정" 화면이 열리고, 부위별 목표 세트 수를 바꿔 저장하면 첫 화면의 남은 세트가 바로 다시 계산된다.
- 목표는 메모리에만 있다. 앱을 끄면 처음 값(가슴 12, 등 12, 하체 9, 어깨 9, 팔 6)으로 돌아간다. 기기 저장은 PRD 일정대로 12주차에 붙인다.

## 2. AI에게 요청한 과정

| 차례 | 내가 한 것 | 이유 |
| --- | --- | --- |
| 1 | PRD F5만 구현하라고 요청. 메모리 저장만, 패키지·상태관리 라이브러리 금지, 먼저 계획만 보여 달라고 함 | 범위가 늘어나지 않게 하려고 |
| 2 | 받은 계획을 읽고, 저장하지 않고 뒤로 가기로 나오는 경우를 추가로 요청 | 계획에 이 경우가 없어서, 그대로 두면 목표가 사라질 수 있었음 |

요청 1회, 계획 검토 후 수정 1회로 총 2회 요청했다. 실행 승인 창에서는 버전 확인·analyze·test 같은 검사 명령만 허용했다.

AI가 끝나고 보고한 내용과 실제 코드를 비교했다. 보고에서는 잘못된 값 테스트가 "기존 목표가 유지되는지"까지 확인한다고 했는데, 실제 테스트는 안내 문구가 나오고 화면이 닫히지 않는 것까지만 확인한다. 저장을 하지 않으니 목표가 바뀌지는 않지만, 테스트로 확인한 범위는 거기까지다.

## 4. 커밋하다가 생긴 일

F5를 커밋하고 push했더니 거절됐다. 원격 저장소에 F4(직전 기록 표시) 커밋 두 개가 먼저 올라가 있었고, 둘 다 `lib/main.dart`와 `test/widget_test.dart`를 고친 커밋이었다. `git fetch`로 어떤 파일이 바뀌었는지 먼저 확인하고 `git pull --rebase`로 합쳤다. 충돌은 없었지만 자동으로 합친 코드가 맞는지 몰라서, push 전에 analyze와 test를 다시 돌려 10개 모두 통과하는 걸 보고 올렸다.

앞으로는 작업을 시작하기 전에 `git pull`부터 한다.
